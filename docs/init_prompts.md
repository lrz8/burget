# agent 开发必读

## 1. 目标边界
这个仓库当前是一个 A 股持仓诊断工具，不是完整的自动交易系统。
已存在的核心链路只有这几段：

1. `src/data` 负责持仓读写。
2. `src/fetcher` 负责行情与资金流抓取。
3. `src/analyzer` 负责 LLM 报告生成。
4. `src/notifier` 负责消息推送。
5. `src/dashboard` 负责 Streamlit 页面。
6. `src/service` 负责主流程编排。
7. `output/` 保存生成结果，`logs/` 保存运行日志。

任何新增需求、改动方案、提示词设计，都必须先服从这个真实边界，不能把“没有采集到的数据能力”写成“已经支持的功能”。

## 2. 第一性原则
每次开始改动前都先确认三件事：

1. 当前需求究竟是在补功能、修逻辑，还是只改文档。
2. 仓库现有代码是否已经有对应模块，优先接入现有链路，不要平地起新系统。
3. 数据源到底提供了什么字段，凡是输入里没有的数据，不允许假装系统已经具备。

如果目标本身不清楚，先收敛需求，不要用兜底描述把实现做虚。

## 3. 工程落地要求
只要发生代码改动，就必须满足下面这些约束：

1. 代码按职责放入现有目录，禁止把抓取、分析、页面、通知混写到一个文件里。
2. 运行时日志必须写入 `logs/`，日志内容至少能定位配置加载、数据抓取、报告生成、保存结果、通知发送这几个关键步骤。
3. 任何生成型结果都必须落盘到 `output/YYYY-MM-DD/`，文件名带时间戳，避免覆盖历史结果。
4. 修改配置相关逻辑时，优先支持环境变量覆盖敏感信息，避免把密钥硬编码进仓库。
5. 改动后必须至少做一轮可执行验证，最低要求是静态检查或可启动验证；如果因网络或外部接口无法完整验证，必须明确写出阻塞点。
6. 只要项目里已经存在服务层，就优先把抓取、分析、保存、通知统一收口到服务层，不要把主流程散落在 UI 按钮或脚本里。

## 4. 数据与分析边界
这是当前项目最容易跑偏的地方，必须严格遵守：

1. 如果行情接口拿到的是日线或收盘级数据，就不能对外宣称“实时分时决策”。
2. LLM 只能基于输入数据做判断，不能补新闻、政策、技术位、主力意图、行业催化等外部信息。
3. 如果数据不足以支撑强结论，报告里必须明确写“数据不足，建议观察”，而不是编造理由。
4. 任何“买卖指令”都必须能回溯到输入字段，例如涨跌幅、成本价、浮盈亏、资金流摘要；不能出现无法验证的分析依据。
5. 页面文案、提示词文案、README 文案必须与真实能力一致，不能一个地方写“盘中实时”，另一个地方实际上只拉到历史日线。
6. 如果已经有规则引擎，就应优先由规则引擎给出稳定动作，再由 LLM 做补充解读，不要把最终动作完全交给 LLM 黑盒决定。

## 5. 方案约束
给出修改方案时，必须遵守以下原则：

1. 优先做主链路闭环，不做花哨但未接线的功能。
2. 不做补丁式堆分支，但也不要为了“架构完美”引入明显超出当前规模的抽象。
3. 新增功能必须说明落在哪个模块、输入输出是什么、如何验证。
4. 禁止只改提示词不改实现，或者只改文档不核对实现，导致描述和行为继续脱节。
5. 如果发现仓库里已经有未接入的模块，例如通知器、输出目录、日志目录，要优先考虑接回主流程，而不是重复造轮子。

## 6. 对本仓库的具体要求
针对当前这个项目，后续改动默认要检查下面这些点：

1. 持仓表字段至少保持 `symbol / name / holdings / buy_price` 这四列稳定。
2. 新增页面按钮或主流程动作时，要处理空持仓、空行情、接口失败、LLM 未配置等边界情况。
3. 生成报告后，默认要考虑三件事是否闭环：页面展示、文件保存、日志记录。
4. 如果通知功能存在，就要么接入真实流程，要么明确标注“未启用”，不能保留悬空实现。
5. 涉及 AkShare 或外部 API 的逻辑，要考虑失败重试、字段兼容和错误提示，不能把异常直接暴露成白屏或未定义变量。

## 7. 修改完成后的自检清单
每次交付前至少自检以下问题：

1. 这次改动有没有让文档描述比真实能力更夸张。
2. 这次改动有没有把输出写进 `output/`。
3. 这次改动有没有把关键过程打进 `logs/`。
4. 这次改动有没有留下未接线的入口、按钮、配置项或类。
5. 这次改动是否说明了验证结果，以及尚未验证的部分。

## 8. 公共仓库隐私要求
如果代码准备推送到公共仓库，必须额外检查：

1. 真实 `API Key`、`webhook`、`sendkey` 只能保留在本地环境变量或本地私有配置中。
2. 真实持仓、监控代码、历史报告、日志文件不能提交到公共仓库。
3. 公共仓库只保留示例模板，例如 `cfg.example.yml`、`portfolio.example.csv`。
4. 如果发现仓库里已有敏感信息，先迁移到本地，再提交和推送。
